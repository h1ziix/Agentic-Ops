## Preserved safety controls

The Planner, Researcher, Reviewer and Outreach agents have typed schemas and no direct workflow/database mutation authority. The Orchestrator owns transitions; checked PostgreSQL completion functions save outputs atomically. AgentRuntime bounds retries. Research uses only the fixed Tavily and Gemini provider endpoints, a bounded response stream and bounded evidence. The application does not directly fetch model-supplied company URLs.

Goals, stored company text and quoted web evidence are marked untrusted in all relevant prompts. Research validation checks citation IDs, supporting quotes, public website rules and score totals. Reviewer validation only accepts supplied evidence and applies confidence/first-party/ICP safeguards. Outreach selects accepted evidence and uses deterministic message composition; it cannot fabricate a contact or grant send authorization. These checks restrict authority and evidence; semantic correctness of web material still requires human review.

The deterministic Executor loads the exact persisted immutable approval snapshot. Revision/digest, recipient provenance, actor/workspace, workflow state and current integration identity/generation are rechecked in SQL before dispatch. Claims and dispatch are persisted before the external mutation. Successful replay returns saved success; concurrent callers do not gain dispatch rights. Completion persistence retries reuse the same provider response. Ambiguous transport/5xx/invalid success bodies become `outcome_unknown`; recovery cannot establish permission to resend. Operator “not found” reconciliation retains uncertainty. Explicit closure for a replacement records duplicate risk and requires a fresh reviewed proposal.

Gmail MIME disables file and URL access and validates single-recipient/header fields. Integration transports use fixed HTTPS provider hosts with redirects disabled. HubSpot previews changed fields, repeats the preview check before mutation and supports read-only exact-field reconciliation. HubSpot cannot make the external preview/write interval atomic; this provider race remains a documented limit.

Signed job callbacks bind the exact request bytes, enforce timestamp/size/schema bounds and carry references rather than actor-supplied content. Durable claims, attempt ceilings, current membership, original follow-up approver and provider-run binding fence delivery. Provider outages/unknown provider status cannot prove a worker stopped. Follow-up timers prepare fresh pending proposals; they never reuse the original email's approval. SQL rechecks cancelled workflows, rejected/responded/converted leads and reply observations before publication and execution.

Provider logs retain allowlisted status/category/timing/IDs rather than tokens, authorization headers, raw model/web payloads or full message bodies. Gemini thought parts are discarded. Observability retains safe summaries, tool correlation/timing and nullable observed usage/cost. Intelligence reads workspace-checked database aggregates with documented cohort semantics; it does not optimize approval policy or prompts automatically.

## Central configuration follow-up audit

The centralized configuration replacement was reviewed against the bundled Next instrumentation guide and the installed Trigger SDK configuration contract. Server getters read lazily and remain behind `server-only`; callers select individual values without serializing the configuration object. Missing optional OAuth, worker and pricing configuration remains explicitly unavailable. Local production startup can serve the isolated demo without invoking those integrations. A requested worker with incomplete configuration raises a safe configuration error instead of silently falling back to browser continuation. Hosted production startup validates core credentials and canonical origins; the selected Planner controls whether OpenAI is required, while the existing research/preparation stack still requires Gemini and Tavily.

Three further configuration defects were hardened:

- **HIGH — fixed:** the Trigger worker's new shared configuration import reached `server-only`, which throws under ordinary Node's default export condition. `trigger.config.ts` now sets the SDK-supported `react-server` build condition. A missing/placeholder Trigger project now fails clearly before worker startup/deploy instead of selecting a fake project. This changes build compatibility, not authorization or delivery behavior.
- **HIGH — fixed:** launch validation missed a privileged public Supabase key with surrounding whitespace, and the public runtime getter accepted server-secret/legacy service-role values. Both now share a browser-safe guard that rejects those values and malformed JWT structures while retaining publishable fixtures and legacy `anon` JWTs. This guard does not verify a JWT signature or grant database authority; Supabase Auth/RLS remain authoritative.
- **MEDIUM — fixed:** hosted loopback rejection could be bypassed by a rooted `localhost` name, other 127/8 addresses or IPv4-mapped IPv6 loopback. The shared canonical-origin rule now rejects these forms on hosted targets, including HTTPS. Local production verification retains canonical loopback support. Malformed/empty model pricing also receives an explicit unavailable warning.

The new configuration file contains **15 passing offline tests**. It covers lazy local production and Edge startup, hosted canonical origins, provider-dependent credentials, public-key safety, partial/missing OAuth, required/malformed worker settings, whitespace provider names, unknown costs and diagnostics that omit configured values. Its worker test builds an in-memory esbuild bundle using the actual Trigger configuration conditions, imports it in ordinary Node with `fetch` guarded, observes no network call and verifies the signing value is not embedded. Missing-project child-process tests verify the CLI configuration boundary. A separate `tsx --conditions=react-server` worker import also passed without invoking a task. Scoped lint and TypeScript checks passed after these changes.

These are offline bundle/import and configuration checks. No Trigger CLI provider deployment, live schedule, callback acceptance or external mutation is claimed. Root release verification records the subsequent full build and complete test totals.
