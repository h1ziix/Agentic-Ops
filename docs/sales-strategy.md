# Saved sales strategy — Release 0.8

ICPs and workflow templates belong to one workspace. Server actions derive the authenticated workspace from cookies, validate with Zod, and call checked database RPCs. RLS limits reads; direct client writes are denied. Create, edit, duplicate and archive each save the mutation and its audit event atomically. Archived records remain readable for management/history and cannot create new workflows. There are no global seeds silently inserted into real workspaces.

Templates provide a default goal, target count, optional default ICP and research guidance. They do not contain executable task lists. The new workflow form submits the explicit user goal and chosen references; the database captures source rows under shared locks in the workflow insert. An explicitly selected ICP overrides a template default. A template with an archived default requires another active ICP or an edited template. Immutable `icp_snapshot` and `template_snapshot` retain the original names and strategy after source edits or archive.

The existing Planner still generates a real validated plan, including its final human approval task. Planner receives the user's goal, compact saved ICP constraints and template execution guidance. Research receives relevant saved ICP constraints. Reviewer receives the same saved ICP and workflow-specific cited research. No agent reloads the current source configuration for an already-created workflow.

The saved minimum score can tighten the existing qualification rule. Its effective threshold is `max(60, saved minimum score)`; existing ICP-fit/evidence component safeguards remain. Positive cited facts matching excluded signal phrases deterministically block qualification/outreach even above the score threshold. Matching is conservative: negated/uncertain phrases are not assertions and partial words do not count. This lexical rule does not infer semantic industry/geography/business-model fit; Reviewer assesses these and required signals against evidence, reporting missing evidence as uncertainty. Scores and weights are never optimized from analytics.

At scoring, a lead captures its exact completed company/workflow research result, research-run reference and qualification outcome/threshold. Later changes cannot rewrite that snapshot, score, confidence, opportunity or scoring explanation. Legacy snapshot enrichment uses only reliable saved research, a recorded qualification audit or original stored score components. It leaves old scores and lead/outreach states untouched, including later Reviewer rejection. Missing historical research remains unavailable; missing scores without qualification evidence retain an unavailable qualification snapshot.

Approval is always required and cannot be disabled by a template. `followup_enabled` is Planner guidance to suggest a later follow-up after confirmed sending. It schedules no job or message. Actual follow-ups retain the existing approved internal-plan/Executor path, confirmed-send provenance and fresh approval for every proposed email. This release adds no external execution path.
